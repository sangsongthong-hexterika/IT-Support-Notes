**Step 4.** Set up DKIM record.

On Zoho > Email Configuration > Select `DKIM`.

I choose `Configure Manually` instead of allowing Zoho to log into my DNS because this is a one time set up. I want to avoid authenticate something and leave the authentication expose and vulnerable. Third-party compromise can become an attack vector. This set up is 1 time thing so doing it manually is not a bad idea.

![adding-dkim-from-zohomail-4.png](./images/adding-dkim-from-zohomail-4.png)

You will see that it is blank at the moment.

![adding-dkim-from-zohomail-1.png](./images/adding-dkim-from-zohomail-1.png)

![zoho-dkim-invalid-selector-1.png](./images/zoho-dkim-invalid-selector-1.png)

**Step 5.** Set up DMARC.

This is the pre-setup DMARC on Zoho.

There are a few questions here to answer before setting up DMARC on Zoho. On a Google Workspace email, the process of this step is different and does not included in their guided setup. However, in this post, I will focus on Zoho setup to avoid confusing. The part about Google, I only mention it to point out that different email provider has different processes but the fundamental idea is the same.

On Zoho's admin panel > Email Configuration > DMARC, you will encounter the questions below. The reason that these questions are important is because DMARC is related to when people contact your email domain about some abusive emails reports. Compare to a Google base you have to set an alias called `dmarc@yourdomain.com`, on Zoho, you have to setup the aliases first and come back here to answer these questions.

![zoho-dmarc-1.png](./images/zoho-dmarc-1.png)

At this point it is worth taking some detour steps to create aliases before coming back here to fill in the below questions. This way you will have an alias ready for any form of abusive reports setup and ready for your internal usage.

***Take a detour step to create aliases emails. Check out the below topic. Then, come back here.***

Come back here to continue.

Take a look at the screenshot below. I filled in those questions with the alias that I have set for abusive reports (aggregate notification and forensics notification).

![zoho-dmarc-2.png](./images/zoho-dmarc-2.png)

Notice that the fields below:

+ Field 1: Action to be taken when DMARC validation fails
+ Field 4: Action to be taken when DMARC validation fails for subdomains
+ Field 5: Policy percentages -> Leave blank.

The idea is to set the lowest restriction available for all of them. This is so that the newly created email inbox has a baseline. Then, I can come back to make some changes or add some rules here later.

After that, click `Generate`. Then, the TXT form will show up. We can use the information from Zoho here to add to CloudFlare' DNS record. For DMARC, the record type is `TXT` type and there is no DMARC type.

To add a DMARC record to CloudFlare.

First taking a look at DMARC TXT record on Zoho.

![zoho-dmarc-3.png](./images/zoho-dmarc-3.png)

Then copy the content and name from Zoho and switch to CloudFlare one at a time to paste on their respective fields as shown below.

![add-dmarc-from-zoho-mail.png](./images/add-dmarc-from-zoho-mail.png)

The below is the successful of DMARC adding checked from Zoho side.

![zoho-dmarc-4.png](./images/zoho-dmarc-4.png)
